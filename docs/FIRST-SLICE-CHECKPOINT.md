# First executable slice — 26 October 2026

The [first-playable follow-up](TICKET19-FIRST-PLAYABLE.md) records the controller,
interpolation, camera and cold-bootstrap work after this historical checkpoint.

This checkpoint delivers a buildable early integration, not completion of issue #19
or the focused mod. See [the current scope and architecture](FOCUSED-READINESS-AND-ARCHITECTURE.md).
All runtime worlds, game resources, native DLLs, raw logs and framebuffer captures
remain local and ignored. No original reference or synced source file was edited.

## Verified

- Java compilation, asset-free tests, JAR assembly and reobfuscation succeeded on
  Java 8u504 / Gradle 4.9 / ForgeGradle 3.0.197 / Forge 14.23.5.2864.
- Native code built locally from pinned libsm64 using LLVM-MinGW 20241001.
  C/JNA sizes matched: surface 44, inputs 20, state 60, geometry 40. State offsets
  action 36, health 32, flags 48 and invincibility 56 matched compiled C.
- Native-only ROM smoke ran two full init/create/run/jump/land/delete/terminate
  cycles: jump peak 117.890045, geometry 752 triangles and health 2176 in each.
  Positions and geometry were finite; the selected ROM hash was verified.
- Timing tests produced 300 steps over 10 seconds at 30/60/144/240 display Hz,
  and verified pause-backlog discard and bounded stall catch-up. These are unit
  checks; display-rate equivalence of the complete game remains unmeasured.
- The real Forge mod loaded a normal generated world. Player/world load/save,
  same-world reload and unload were observed. Earlier probe teardown produced
  queued vanilla packet errors; this does not establish completed persistence.
- Integrated gameplay probe 7 exercised standing, running, jump and landing on
  the existing generated terrain. It observed 15.200765 blocks of total travel
  and a 3-block rise in that particular route. These are not flat-floor physics
  tolerances or a claim of exact reference equivalence.
- Probe 7 native attack admission occurred 3 times. Two server-side 4-point hits
  changed a test pig's health 10→6→2. This deterministic fixture had NoAI enabled
  only in probe code; it is not evidence of ordinary mob pursuit or pathfinding.
- The stationary client/server position discrepancy was 0.0 blocks, sampled at
  client native frame 340 / server world tick 3686, against a 0.05-block limit.
  No moved-wrongly or moved-too-quickly warning occurred in that run.
- A private framebuffer showed recognizable Mario geometry and base colors in
  the normal world. Rendering is currently unlit. The test selected a clear
  camera angle for visual QA; this is not camera obstruction acceptance.
- Native teardown, player/world save/unload and a successful Gradle process exit
  were observed after the integrated probe.
- The final probe 8 also passed: 2 native admissions and 2 accepted server hits,
  zero stationary pose error, 25.742834 blocks of route travel and 2.733365 blocks
  of jump rise. Separately sampled ordinary AI-enabled mobs had ticked up to
  499 entity updates since loading. This verifies continued entity updates with
  AI enabled, not every navigation or attack behavior. The deterministic contact
  pig remained a separate NoAI fixture. No movement-validation warning occurred.

## Repairs established during implementation

The guarded issue #34 Side.class replacement remains required and is invoked by
`scripts/dev.ps1`. ForgeGradle's inherited `forceExit` run setting also attaches
`System.exit(0)` to the Gradle task itself. Explicit `forceExit false` preserves
the forked game process and allows Gradle to finish successfully.

Native creation waits for a populated client chunk and nonempty block collision
geometry. Empty geometry must not call JNA `Structure.toArray(0)`.

The libsm64 texture atlas is an alpha overlay: render the colored geometry base,
then the textured overlay. Multiplying the entire mesh by transparent atlas
texels initially produced a dark silhouette; that renderer was replaced.

The real player identity is retained. Active single-player native ownership
suppresses only outbound vanilla movement packets. Other packets, including
teleport confirmations, are forwarded. Server pose application occurs at server
tick END: the mapped NetHandlerPlayServer.update restores its captured position
after onUpdateEntity, so a LivingUpdate assignment alone is overwritten. The
movement gate is removed and settings restored when native ownership closes.

## Remaining work

Issue #19 remains open: controller input and comprehensive integrated validation
are absent; rendering interpolation is not yet connected. The camera is a
baseline using vanilla obstruction handling; tight terrain can collapse it into
Mario's cap. Exact camera controls/modes and this obstruction defect need work.

Incoming damage is not yet translated into native Mario health/reactions.
Outgoing damage 4 and the contact cooldown are provisional crossover choices.
Swimming/hazards, broader combat, settings, final character presentation, safe
persistence and final packaging are not complete. No full research or MVP ticket
is declared complete by this checkpoint.

## Provenance and reproduction

Use the commands in [README](../README.md). The existing-cache build/run path was
tested; the complete fresh-bootstrap path is still unverified. Official Gradle
4.9 wrapper scripts/JAR were copied from the previously verified Forge MDK;
their upstream Gradle distribution is Apache-2.0 licensed. The distribution URL
and SHA-256 are pinned in gradle-wrapper.properties. Native archive versions,
hashes and libsm64 source commit are pinned in bootstrap scripts. Native imported
Mario geometry and the resulting DLL remain local; upstream's CC0 declaration
is not represented as clearing game assets.

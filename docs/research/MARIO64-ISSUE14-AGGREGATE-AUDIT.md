# Mario 64 object, enemy, and interaction aggregate audit (#14)

**Draft for root review.** GitHub issue #14 remains open. Its five original acceptance criteria remain unchanged and unchecked. Current child states were fetched from GitHub on 2026-10-26: #52, #53, #54, and #55 are closed; #56 remains open. This report audits the evidence without changing those tracker boxes or claiming parent completion.

## Evidence boundaries

The target is the USA revision 0 ROM (SHA-256 `17CE077343C6133F8C9F2D6D6D9A4AB62C8CD2AA57C40AEA1F490B4C8BB21D91`). The dossiers combine canonical target-code/data analysis, pinned source-navigation evidence, and sanitized Project64 scalar observations. Static correspondence, structural script candidates, and runtime execution are separate evidence classes. Project64 samples use bounded read-only sampling and are not atomic snapshots. No ROM or RAM bytes, derived assets, save states, screenshots, raw captures, or private host paths are included here.

## Bounded follow-up #60

**Title:** Expand representative Mario enemy-family AI and projectile-contact coverage

**Parent:** #14. **Depends on:** #52, #53, #54. **Out of scope:** repeat of the five-action matrix, course placement/progression, pickups, platform rider mechanics, and implementation.

Use the finite #54 candidate set as the discovery boundary. The 17 rows without family-path coverage are `bhvMrI`, `bhvKingBobomb`, `bhvChuckya`, `bhvThwomp`, `bhvSpindrift`, `bhvBowser`, `bhvPiranhaPlant`, `bhvBub`, `bhvBoo`, `bhvScuttlebug`, `bhvBobomb`, `bhvKoopa`, `bhvChainChomp`, `bhvMontyMole`, `bhvSnufit`, `bhvKlepto`, and `bhvSkeeter`. First reconcile these rows against exact target code/data and preserve ambiguous structural matches as candidates only. Then select reachable specimens that add behavior/contact/projectile evidence beyond #54; Fly Guy and Unagi remain eligible because their current evidence is static only. For selected specimens, pair target-ROM paths with controlled Project64 observations of AI state, Mario body contact, and defeat/survival/removal. Check Mario projectile contact where a selected emitter/payload is reachable; distinguish this from ground/geometry contact. Retain unselected families and action/target rows as untested. Publish only sanitized scalar observations and numeric/hash references. Keep the issue open for unavailable scenarios rather than inferring outcomes.

The follow-up is [issue #60](https://github.com/BrantTanner/MarioCraft/issues/60). It depends on completed #52/#53/#54 only, avoiding a dependency cycle through #14. It does not absorb #56's already-open controlled coin/healing/one-up work.

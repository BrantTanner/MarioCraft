# Mario 64 USA analog input and deadzone sweep — issue #37

Status: **dynamic calibration complete for bounded keyboard-generated samples**. This closes the intermediate-value, deadzone, and diagonal-cap measurements for the tested original USA ROM and Project64 setup. The public sanitized vectors are in [the companion JSON trace](mario64-issue37-analog-sweep-sanitized.json); a read-only sampler is in [issue37-analog-sampler.js](issue37-analog-sampler.js).

## Verified ROM behavior

The target is the USA revision 0 ROM, SHA-256 `17CE077343C6133F8C9F2D6D6D9A4AB62C8CD2AA57C40AEA1F490B4C8BB21D91`. The byte-verified mapping is ROM offset `0x1000` → RDRAM `0x80246000`, valid through ROM offset `0xE855F` before the first mismatch.

The controller sampling routine at ROM `0x3638..0x3700` (runtime PC `0x80248638..0x80248700`) reads each controller record at stride `0x1C`, follows its controller-data pointer at record offset `+0x18`, and copies signed raw X/Y axes into record halfwords `+0` and `+2`. The runtime sampler reads the current record pointer from the candidate Mario structure at `+0x9C`, then reads raw axes at record `+0/+2`, processed float axes at `+4/+8`, and magnitude at `+0x0C`.

The adjustment routine at ROM `0x3304..0x3490` (PC `0x80248304..0x80248490`, range SHA-256 `838339138778394a85c54ba7d81bb34013cc6df45f036a84cafd0c9994f56108`) first maps raw values from `-7` through `+7` to zero. Values at or below `-8` receive `+6`; values at or above `+8` receive `-6`. It calculates Euclidean magnitude and scales both components when the result exceeds `64.0`, storing magnitude `64.0`.

The dynamic measurements agree with this transform. At N-Rage range 6%, the keyboard plugin produced raw axes of ±7 cardinally and (±5, ±5) diagonally; all processed values were zero. At 7%, raw cardinal ±8 became ±2, while the (±6, ±6) diagonals remained zero. At 10%, stable raw cardinal ±12 became ±6 and raw (±8, ±8) became (±2, ±2), magnitude about 2.828427. Transition samples also included raw cardinal ±9→±3. At 100%, raw cardinal ±127 became approximately ±63.999996, magnitude 64. The diagonal (±89, ±89) became approximately (±45.254833, ±45.254833), also magnitude 64, dynamically confirming radial scaling to the ROM's cap.

The complete sanitized set of stable, input-correlated values and sample counts appears in the companion JSON, along with four selected actual records per helper hold (pre-input, edge, held, first sample after key-up). The transition rows were retained in the local traces but are not presented as calibration plateaus. All four runs captured 7,200 rows; the candidate counter at `0x8032D5D4` matched before and after every row. It advanced by 3,599–3,600 over roughly 120 seconds. Recomputing the exact-ROM transform for all 28,800 raw axis pairs matched every runtime value within a maximum absolute component difference of `0.000003814697265625` (the endpoint float representation); ranges 6, 7, and 10 matched exactly. The callback is `events.ondraw`, so it is a host-driven draw observation, not an emulated frame. Equal counter brackets do not guarantee that every field was read atomically.

## Reproduction

Use the untouched USA ROM and the isolated Project64 portable build `3.0.1.5664-2df3434` (SHA-256 `C257C662D4E0B2CE1732B7F4A7D5DD4682F604CB082BBDBFCE5181470D6DBFB8`). For the captures in this report, the loaded input module was N-Rage Input V2 `3.0.1.5664-2df3434`, DLL SHA-256 `8B06D0BC29DEC6233640400E15051B945923BB6283E290B40AF64016992E6C20`. Controller 1 was plugged and mapped to keyboard arrows for its analog directions. N-Rage's `Real N64 Range` was enabled and its own `PadDeadZone` configuration value was 5 for every sweep. These are Project64 input-plugin settings; the ROM's fixed raw-axis deadzone is a separate transform.

Restore `issue35-mario-gameplay-baseline.pj.zip` through the Project64 UI with F7 before each run. Its SHA-256 is `6E2C8265A8A9A19761BCC6CE29FA20694FAD5444B325B1F22CA987776A2D6DFE` (1,387,126 bytes); the screen was checked for the courtyard, lives ×4, and stars ×0. Open the N-Rage Controller 1 Controls tab, set `Range` to 6%, 7%, 10%, or 100%, leave `Real N64 Range` enabled and `PadDeadZone` at 5, then save the plugin setting. Copy [issue37-analog-sampler.js](issue37-analog-sampler.js) into Project64's Scripts folder. Stop any stale script marked Running. Set a fresh, unique output path and trial ID containing a timestamp, set matching `rangePercent`, run the script, and verify its new started marker before applying helper inputs. Use [issue37-project64-input.ps1](issue37-project64-input.ps1) to generate guarded 350 ms cardinal and diagonal holds for ranges 6/7/10, or 500 ms holds for range 100. The helper accepts either the installed or issue11 portable Project64 target, pinned to the verified executable path and binary hash, and whitelisted input keys. It checks the foreground PID/HWND/title, allows at most three simultaneous keys, and always releases keys. Its SHA-256 is `B0712C4C7EBF97BFFF69D0B0D73D7A553DEDE9BD183831CB8ACBB2AD25E38473`; the sampler SHA-256 is `C57356AA188FF7DC0FA4D6C8B4F33BF10DED31FEA4CEC348363A9E8DC1CC01A6`. The companion JSON includes four time-relative selected rows (baseline, input edge, held, and release) for every guarded hold, plus the stable-vector sample counts.

The sampler uses only the old build's `events.ondraw`, `events.remove`, `mem.u32`, `mem.s16`, `mem.u16`, `mem.float`, `Date.now()`, and `fs.writeFile` APIs. It bounds each run at 7,200 valid pointer samples and 14,400 total callback invocations (not elapsed wall time; a paused or stalled host may take longer), validates the controller pointer is in the expected RDRAM range, reads memory without writing to it, and removes its callback after one output write. Point `tracePath` to a writable local destination; do not publish raw RAM traces or save states.

## Evidence and limits

Each full local trace is a 7,200-row capture. Their SHA-256 values are included in the companion JSON so the sanitized observations retain provenance without publishing full memory-address traces. The capture outputs, helper logs, ROM, and state archive remain local. Earlier attract/demo-screen captures and attempts without an aligned bounded sampler and guarded input window were excluded. At the end, the portable emulator was closed and its active `Project64.cfg` was restored byte-for-byte from the local pre-N-Rage clone backup; the restored file selects the Project64 input plugin and stores Controller 1 `Deadzone=1` and `Range=5` (SHA-256 `8A928DE3F1C4BA8A5ABFD9ECB3675FC07C6AC06A391FF4621955A9E6D3F0CCFA`). This is a clone-local restoration; the installed Project64 configuration was not changed. The N-Rage-selected config and final N-Rage INI used for the 100%/PadDeadZone-5 capture were preserved as ignored local snapshots for later calibration work.

This experiment calibrates repeatable keyboard-generated values through one version of the Project64 N-Rage plugin. It does not characterize physical controller hardware or every plugin revision. The plugin source for this exact bundled build was not independently matched, so no N-Rage scaling formula is inferred from these measurements. Draw-callback timing and paired counter reads have the limits described above.

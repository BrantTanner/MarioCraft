# Mario 64 special surfaces: integrated inventory and evidence (#43)

This dossier reconciles the original #43 work with the completed [USA rev0 consumer census (#45)](MARIO64-ISSUE45-SPECIAL-SURFACE-CENSUS.md) and [bounded water/lava runtime study (#46)](MARIO64-ISSUE46-WATER-LAVA-RUNTIME.md). The current per-ID crosswalk is [mario64-issue43-surface-inventory.csv](mario64-issue43-surface-inventory.csv). Together, these files cover the finite 147-ID source-derived candidate list and the target branches found by the documented bounded search. They do not establish that every candidate is placed in an active level or prove universal absence outside the searched code and data.

## Target and evidence rules

The target is Super Mario 64 USA rev0, 8 MiB, ROM SHA-256 `17CE077343C6133F8C9F2D6D6D9A4AB62C8CD2AA57C40AEA1F490B4C8BB21D91`, measured with Project64 `3.0.1.5664-2df3434` (SHA-256 `C257C662D4E0B2CE1732B7F4A7D5DD4682F604CB082BBDBFCE5181470D6DBFB8`). Source-navigation names are pinned to `n64decomp/sm64@9921382a68bb0c865e5e45eb594d9c64db59b1af`; they help interpret numeric target behavior and are not proof of the shipped target's names.

For the validated main-code map, `PC = 0x80245000 + ROM offset` applies only to ROM offsets `0x1000..0xE855F`. Ranges are half-open and hashes cover exact USA rev0 bytes. Engine functions outside that map are reported only when their complete function envelopes were independently byte-matched to a ROM offset; the main-map base is not extrapolated to them. The original ROM was preserved and the analysis copy was loaded byte-identically. Runtime sampling used external read-only process reads; the sampler brackets fields with a loop counter but does not produce atomic frame snapshots. No ROM, save state, asset, or raw emulator capture is published.

## Runtime provenance and interpretation

The original #43 trial 06 reached a steep type `0x13` floor before sliding back downhill. The route driver had a hashtable access bug, so every active pulse resolved to AnalogUp; the corrected driver was syntax-checked but not replayed. Trial 06 therefore supports only the observed uphill-input slope trajectory and its negative-speed reversal. It is retained as failed route history, not water runtime evidence. The earlier in-box #43 field read likewise remains a dry-floor observation.

#46 supersedes the old statement that water entry/swimming and lava/burn runtime were unverified. Its water record contains one bounded entry and a swimming stroke, with a sampled trace and exact-ROM correlations. Its lava record used a temporary one-byte save-flag fixture only to pass the basement door; Project64 reverted the byte when cheats were disabled, and all cheats were off during course measurement. This was not natural-progression evidence. The lava capture has repeated counter values and inconsistent late candidate floor-type reads at the same pointer; only the contact-time type-1 samples support the contact/action statement. No health field was instrumented.

## Remaining limits and scope

The 45 painting-dispatch IDs (`0xA6..0xD2`) have target GEO_ASM records and a verified parser/render callback path, but configured painting-index-to-ID mapping remains unresolved. The grouped `0xD3..0xFF` table lookup verifies a range and a conditional height predicate for `0xFD..0xFF`; it does not prove a nonzero active-level entry for every candidate. Static target consumers do not establish placed geometry or runtime traversal.

Issue #1 excludes portals and Mario course objectives from the MVP. Camera, painting, timer, music, and course-specific candidates remain in the research inventory with row-level scope notes; exclusions do not erase the evidence or convert uncertain mappings into established behavior. Moving-platform transforms are handled as object behavior, separate from surface identity.

No exact per-surface friction coefficient is claimed. No damage/healing amount or health decrease is claimed here; #46 observes lives, not health, and MarioState `+0xB2` remains unlabeled. Runtime contact for quicksand, wind/current, hanging, death planes, and the camera/painting/course-only families remains unobserved in these follow-ups. These are bounded runtime gaps rather than evidence that the corresponding static branches are absent.
